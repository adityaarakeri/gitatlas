# Translating the viewer

The generated map's UI is translatable. Nothing else in the project is, and that is deliberate: [TRANSLATE.md](../TRANSLATE.md) is the plan of record and explains what stays English and why.

## Status

| Locale | Name | Reviewed by | State |
| --- | --- | --- | --- |
| `en` | English | source text | shipping |
| `zh-CN` | 简体中文 | nobody yet | machine draft |
| `ja` | 日本語 | nobody yet | machine draft |
| `es` | Español | nobody yet | machine draft |
| `pt-BR` | Português (Brasil) | nobody yet | machine draft |

A machine draft is a first pass with no human sign-off. It ships in the file and is selectable, but `reviewed` is `false` in its catalog and this table says so. An unmaintained translation carries the project's authority while teaching readers things that are not true, so the honest label matters more than the coverage number.

To claim a locale: read it end to end against a real map, fix what is wrong, then set `reviewed: true` and put your handle in `maintainer`. A test refuses `reviewed: true` without a named maintainer.

## How it works

- Catalogs are JSON at `packages/viewer/locales/<code>.json`, one flat `key -> string` map each.
- `extract` bakes every catalog into the generated HTML. Four extra languages cost about 4 KB against a file that already carries d3, which buys "one file anyone can open" instead of one file per language.
- The viewer picks `navigator.language` on open, falls back to English, and shows a picker beside the theme toggle when the file carries more than one language. `gitatlas extract --lang <code>` pins the default instead.
- `packages/viewer/template.html` keeps its English text inline in the markup and carries `data-i18n` attributes beside it. The active catalog overwrites that text on load, so the template still reads as a working English page on its own.

## Adding a locale

1. Copy `packages/viewer/locales/en.json` to `<code>.json`. Use the BCP 47 tag readers actually have (`pt-BR`, not `pt`).
2. Set `locale` to the filename, `name` to the language's name in that language (it is what the picker shows), `reviewed` to `false`, `maintainer` to your handle.
3. Translate the values. Keep every key: `npm test` fails on a key set that has drifted from `en.json`, because a half-translated panel reads as a bug rather than a gap.
4. `npm run extract -- fixtures` and open the map. Switch to your locale and walk all four levels.

Nothing else needs touching. The extractor reads the directory, so a new file is picked up on the next run.

## Rules for the copy

- **Rewrite, do not transliterate.** "Tap a node to open it" should become the sentence your language would actually use.
- **Match the existing voice**: plain, active, no em dashes.
- **Keep the glyphs.** `┄`, `◎`, and `→` appear inside legend strings and are the visual key the sentence refers to.
- **Leave `{name}` placeholders alone**, spelling included. A test asserts each string carries the same placeholders as English.
- **Do not translate identifiers.** Command names, flags, file paths, and schema values (`repo`, `module`, `function`) are data. Only their display labels under `kind.*` are translated.

## Plurals

A value is either a string or a map of CLDR plural categories:

```json
"badge.files": { "one": "{n} file", "other": "{n} files" }
```

The viewer selects with `Intl.PluralRules`, so use the categories your locale actually has: Chinese and Japanese need only `other`, English needs `one` and `other`. A test fails on a category your locale never selects, and `other` is required everywhere as the fallback.

Where English is a plain string, your catalog must be a plain string too, and vice versa. If a language needs a plural where English does not, make the change in `en.json` first so every catalog agrees.

## What the tests enforce

`packages/extractor/test/i18n.test.ts` fails the build on: a key set that differs from English, a blank value, a plural map where English has a string, a placeholder that does not match, a plural category the locale cannot select, `reviewed: true` with no maintainer, a template key with no catalog entry, and a catalog key the template never uses.
